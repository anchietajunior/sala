Aula 01 — Início do projeto e frameworks

Duração: ~2h  ·  Branch: aula-01-inicio-do-projeto-e-frameworks

Temas teóricos: o que são frameworks [T-1] · modelo cliente-servidor [T-2] · gerenciamento de dependências [T-6]

Objetivos — ao final, o aluno consegue:

  • Descrever o modelo cliente-servidor e apontar quem é cliente e quem é servidor em um acesso real;
  • Explicar o que um framework resolve e a diferença entre framework e biblioteca;
  • Criar um ambiente virtual Python e instalar dependências com pip (Mac e Windows);
  • Registrar dependências em requirements.txt e explicar por que isso importa;
  • Implementar e executar a primeira rota FastAPI, testando-a no navegador.

10 min Abertura — o que vamos construir neste semestre

Apresente a disciplina pelo produto final, não pela ementa: um Reading Tracker — sistema web onde cada pessoa cadastra seus livros, envia a capa, registra em que página está e acompanha a porcentagem de leitura. Haverá cadastro, login, área administrativa e até relatório em PDF.

  • Mostre um esboço rápido no quadro: telas de login → lista de livros com % → dashboard admin.
  • Explique o método da disciplina: toda aula evolui o mesmo projeto. A teoria aparece na hora em que a prática precisa dela.
  • Hoje: a fundação — entender onde o código vai rodar (cliente-servidor), com que ferramenta (framework) e como instalar essa ferramenta direito (dependências).

15 min Teoria [T-2] — o modelo cliente-servidor

Pontos a explicar:

  • Dois programas conversando pela rede: o cliente pede, o servidor responde. Nunca o contrário.
  • No nosso projeto: o navegador (e depois o React) é o cliente; o backend FastAPI é o servidor.
  • A conversa tem um idioma: HTTP — pedido (request) e resposta (response). Aprofundamos na aula 02.
  • O servidor não sabe quem vai chamar nem quando: ele fica esperando requisições.

Analogia sugerida: restaurante — o cliente (mesa) faz o pedido, o garçom (HTTP) leva à cozinha (servidor), a cozinha prepara e devolve o prato (resposta). A mesa não entra na cozinha.

Para a turma: "Quando vocês abrem o Instagram, o que é cliente e o que é servidor? E quando o feed atualiza sozinho, quem pediu?"
Para a turma: "O site sai do ar. O problema pode estar no cliente ou no servidor? Como vocês descobririam?"

15 min Teoria [T-1] — o que é um framework

Pontos a explicar:

  • Receber uma requisição HTTP "na unha" significa ler bytes de um socket, interpretar o protocolo, montar a resposta byte a byte. Ninguém escreve isso a cada projeto.
  • Biblioteca: você chama o código dela quando quiser. Framework: ele te chama — você preenche as lacunas (a rota, a regra de negócio) e ele cuida do fluxo. É a inversão de controle ("princípio de Hollywood: não nos ligue, nós ligamos para você").
  • O FastAPI é nosso framework web: recebe a requisição, descobre qual função sua deve responder, converte o retorno em JSON.
  • Frameworks trazem decisões prontas — bom (produtividade, segurança) e ruim (menos liberdade). Essa troca vale quase sempre.
Para a turma: "Quem controla o main() do nosso programa quando usamos FastAPI? Nós ou ele?" (resposta: ele — nós só declaramos funções e ele decide quando chamá-las)

15 min Teoria [T-6] — dependências e ambientes virtuais

Pontos a explicar:

  • FastAPI é uma biblioteca de terceiros: não vem com o Python. Alguém escreveu, publicou no PyPI, e o pip baixa de lá.
  • Problema: projetos diferentes na mesma máquina podem exigir versões diferentes da mesma biblioteca. Solução: ambiente virtual (venv) — uma "caixa de ferramentas" isolada por projeto.
  • requirements.txt é a lista de compras do projeto: qualquer pessoa (ou servidor) reproduz o ambiente com um comando.
  • Versões têm significado (semver: MAJOR.MINOR.PATCH) — mencionar de passagem, sem aprofundar.
Para a turma: "Vocês entregam o trabalho e na máquina do professor não roda. O que pode ter de diferente entre as duas máquinas?"

35 min Live-coding — do zero à primeira rota

Passo 1 — criar a pasta do backend e o ambiente virtual

Por quê: isolar as dependências deste projeto das do resto da máquina.

Mac 
mkdir -p projeto/backend
cd projeto/backend
python3 -m venv .venv
source .venv/bin/activate
Windows (PowerShell) 
mkdir projeto\backend
cd projeto\backend
python -m venv .venv
.venv\Scripts\Activate.ps1

Mostre o (.venv) aparecendo no prompt — é o sinal de que a caixa de ferramentas está aberta. Peça para todos confirmarem antes de seguir.

Se o Windows bloquear a ativação ("execution policy"), rode uma vez: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser e abra o PowerShell de novo.

Passo 2 — instalar o framework e o servidor

Por quê: FastAPI é o framework; uvicorn é o servidor web que o executa (a distinção fica clara na aula 02).

Mac e Windows (iguais, com o venv ativo) 
pip install fastapi uvicorn

Passo 3 — registrar as dependências

Por quê: sem isso, o projeto só roda na sua máquina.

pip freeze > requirements.txt

Abra o arquivo e mostre: as bibliotecas que instalamos e as que vieram junto (dependências das dependências). Explique que um colega reproduziria tudo com pip install -r requirements.txt.

Passo 4 — a primeira rota

Por quê: aqui o framework aparece em ação — declaramos uma função e ele cuida de todo o HTTP.

Criar main.py dentro de projeto/backend:

from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"message": "Welcome to the Reading Tracker API"}

Digite devagar e explique linha a linha: importamos o framework, criamos a aplicação, e o decorator @app.get("/") diz ao FastAPI "quando chegar um GET na raiz, chame esta função". O dicionário Python vira JSON automaticamente — trabalho do framework.

Passo 5 — subir o servidor

Mac e Windows (iguais, com o venv ativo) 
uvicorn main:app --reload

Explique a sintaxe: main é o arquivo, app é a variável dentro dele. O --reload reinicia o servidor a cada mudança no código — só para desenvolvimento.

Passo 6 — versionar o início do projeto

Por quê: o .venv é reconstruível e enorme — nunca vai para o repositório; o requirements.txt é o que se versiona.

Criar .gitignore em projeto/backend:

.venv/
__pycache__/

Criar README.md em projeto/ (em pt-BR — código em inglês, documentação em português) com o mínimo para alguém rodar o que existe hoje, mais a Tabela de Dependências espelhando o requirements.txt:

# Reading Tracker

Projeto da disciplina Programação Avançada: um rastreador de leituras
construído com FastAPI e React.

## Backend — como rodar

    cd backend
    python3 -m venv .venv          # Windows: python -m venv .venv
    source .venv/bin/activate      # Windows: .venv\Scripts\Activate.ps1
    pip install -r requirements.txt
    uvicorn main:app --reload

Abra http://127.0.0.1:8000

## Tabela de Dependências

| Nome | Utilidade | Versão |
| ---- | --------- | ------ |
| fastapi | Framework web: rotas, validação e documentação automática | 0.139.2 |
| uvicorn | Servidor web que executa a aplicação | 0.51.0 |
| ... (uma linha por entrada do requirements.txt) | | |

Instalamos diretamente apenas **fastapi** e **uvicorn**; as demais
vieram como dependências delas.
A tabela completa tem uma linha por pacote do requirements.txt — não digite em sala: cole a versão pronta do repositório e gaste o tempo lendo a utilidade de cada pacote com a turma (reforça o tema de dependências das dependências).
Checkpoint — como saber que funcionou:
  • Navegador em http://127.0.0.1:8000 mostra {"message": "Welcome to the Reading Tracker API"}.
  • Com o servidor rodando, mude o texto da mensagem, salve e recarregue a página — a turma vê o --reload agir.
  • Teaser: abra http://127.0.0.1:8000/docs por 30 segundos: "o framework documentou nossa API sozinho — semana que vem exploramos isso". Não aprofunde.

15 min Exercício em sala

Individual, com o que acabou de ser visto:

  1. Criar uma rota GET /status que responde {"status": "ok"}.
  2. Criar uma rota GET /about que responde um JSON com project (nome do projeto) e author (nome do aluno).
  3. Testar as duas no navegador.

Gabarito (para o professor):

@app.get("/status")
def read_status():
    return {"status": "ok"}


@app.get("/about")
def read_about():
    return {"project": "Reading Tracker", "author": "Student Name"}

Circule pela sala: os erros clássicos serão venv desativado (ModuleNotFoundError: fastapi) e esquecer de salvar o arquivo.

5 min Fechamento

  • Síntese: cliente pede, servidor responde; o framework cuida do HTTP para nós; o venv + requirements.txt tornam o projeto reproduzível.
  • Gancho para a aula 02: "Hoje digitamos um endereço e apareceu um JSON. Mas o que acontece entre uma coisa e outra? Como o navegador achou o servidor? O que exatamente viajou pela rede? Semana que vem, dissecamos essa viagem — incluindo o DNS e o papel real do uvicorn."
