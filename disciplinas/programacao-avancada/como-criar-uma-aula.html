Como criar uma aula — fluxo de iteração

Cada aula da disciplina produz quatro artefatos que precisam contar a mesma história:

📄 Roteiro do professor (aulas/aula-NN/roteiro.html) 🎞️ Slides do aluno (projeto/slides/aula-NN/slides.html) 🌿 Branch (aula-NN-slug em projeto/) 📘 projeto/README.md atualizado

O fluxo abaixo usa as três skills do projeto (.claude/skills/) dentro do Claude Code. O escopo de cada aula já está definido em docs/plano-de-aulas.md; as regras de formato, em docs/convencoes.md.

Atalho — comando único: peça cria a aula NN e a skill aula-completa executa os passos 1 a 6 de uma vez (roteiro → código na branch → slides → sync). O passo a passo abaixo continua valendo para rodar cada etapa separadamente.

Passo a passo

1. Confira o escopo.

Abra docs/plano-de-aulas.md e localize a aula NN: quais temas teóricos [T-n] ela cobre e o que o live-coding constrói.

2. Crie a branch da aula.

A branch nasce de onde a aula anterior terminou (formato slug, sem espaços):

cd projeto
git checkout aula-02-ciclo-de-vida-de-uma-requisicao   # branch da aula anterior
git checkout -b aula-03-apis-rest-e-uris               # nova branch
3. Gere o roteiro do professor.

No Claude Code, peça:

escreva a aula 03

A skill aula-roteiro lê o plano, as convenções, o glossário (CONTEXT.md) e a branch anterior, e gera aulas/aula-03/roteiro.html com teoria, live-coding passo a passo (comandos Mac e Windows) e exercício.

4. Implemente o código na branch.

Siga o live-coding do roteiro dentro de projeto/ — o código da branch deve ficar idêntico ao do roteiro. Commite na branch da aula:

git add .
git commit -m "aula 03: REST routes for books (in-memory)"
5. Gere os slides do aluno. 
slides da aula 03

A skill aula-slides gera o deck reveal.js (tema claro) a partir do roteiro, com diagramas em SVG e referências bibliográficas por tema.

6. Feche a aula com a sincronização. 
sincroniza a aula 03

A skill aula-sync roda o checklist: branch bate com o roteiro (git diff contra a aula anterior), slides batem com o roteiro, termos conforme o glossário, ADRs respeitados e projeto/README.md refletindo o estado até esta aula. Só considere a aula pronta com o checklist verde.

Primeira iteração (Aula 01)

Na primeira aula ainda não existe repositório. Antes do passo 2:

cd projeto
git init
git commit --allow-empty -m "start of the course project"
git branch -M main
git checkout -b aula-01-inicio-do-projeto-e-frameworks

O README.md nasce na própria aula 01, junto com o backend — e evolui a cada aula seguinte.

Regras que valem para toda iteração

  • Ordem dos artefatos: roteiro → código → slides → sync. Slides nunca divergem do roteiro; roteiro nunca diverge do código.
  • Código todo em inglês; material didático em português.
  • Legibilidade acima de performance — é código para ensinar.
  • Decisões registradas em docs/adr/ valem para todas as aulas (ex.: ADR-0001, rotas nascem sem auth até a aula de JWT).
  • O README nunca menciona aulas futuras.
